# Expectation

This page defines expectation as a structured anticipation inside the architecture.

## Purpose

Explain what an expectation is, why it matters, and how it differs from raw desire, prediction, or moral judgment.

## Core Idea

An expectation is a structured anticipation held by the system before or during an event. It represents some model of what is likely to happen, what is wanted, or what should happen. Expectations are central to the architecture because emotional impact is driven less by events alone and more by the gap between expectation and actual outcome.

The system does not process events in a vacuum. It processes them against active expectations. This is what allows the model to explain why the same event can be emotionally insignificant in one context and highly meaningful in another.

## What Makes an Expectation Important

An expectation matters because it creates a reference point. Once the actual outcome arrives, the system can compare reality against that reference point and measure discrepancy.

For example:
- if no positive response was expected, silence may mean very little
- if support was strongly expected, silence may become painful
- if respect was believed to be deserved, disrespect may create anger even if it was predicted

This means expectation is not only a forecast. It is part of the emotional structure of interpretation.

## Expectation as a Structured Object

An expectation should not be treated as a vague feeling. It is better understood as a structured object with elements such as:
- expectation type
- anticipated outcome
- confidence
- importance
- rigidity
- source
- scope
- time relevance

These elements help explain why some expectations have little emotional force while others become central to emotional impact.

## Main Expectation Families

The architecture distinguishes among several expectation families:
- predictive expectation
- desired outcome
- deserved outcome

These are separated because they produce different kinds of discrepancies and different kinds of emotional consequences.

## Why Expectation Must Be Explicit

If expectations remain implicit, the architecture loses one of its main advantages. It may still record that an event caused distress or relief, but it will not be able to explain why.

Making expectations explicit allows the system to answer questions such as:
- what was I expecting at the time?
- how sure was I?
- why did I care so much?
- what belief made this event feel unfair?
- what would have made this event feel less damaging?

These questions are central to both auditability and reflection.

## Expectations Change Over Time

Expectations are not fixed forever. They are revised by:
- repeated experience
- relationship change
- insight
- repair
- reflective adjustments
- changing self-state

This means the architecture should preserve not only current expectations, but also enough history to understand what expectation was active at the time of a past event.

## Design Rule

An expectation should always be specific enough to compare against an actual outcome and meaningful enough to explain why that outcome had emotional impact.
