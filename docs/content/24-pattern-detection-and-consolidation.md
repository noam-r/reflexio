# Pattern Detection and Consolidation

This page explains how repeated events become higher-order patterns.

## Purpose

Show how the architecture moves from isolated event processing to longer-term narrative and structural understanding.

## Core Idea

Not every meaningful change comes from one event alone. Sometimes what matters is the repetition of similar events over time. Pattern detection is the process of recognizing these repeated structures. Pattern consolidation is the process of turning them into higher-order meaning that can affect expectation, appraisal, relationship state, or self-state.

This allows the architecture to move beyond isolated moments and recognize things like:
- repeated dismissal
- growing trust
- unstable warmth
- recurring rupture and repair
- increasing reciprocity
- emotional inconsistency

## Why Pattern Detection Matters

Many emotional realities are not visible in single events. One event may be ambiguous. A pattern is often clearer.

For example:
- one cold reply may mean very little
- five cold replies after meaningful bids for connection may indicate distance or disregard

Pattern detection allows the system to identify this difference.

## What Counts as a Pattern

A pattern may involve repetition across:
- event type
- appraisal type
- relationship effects
- discrepancy shape
- repair attempts
- expectation violations
- emotional outcomes

Patterns do not have to be purely negative. The architecture should also be able to detect:
- consistent care
- dependable repair
- repeated acknowledgment
- stable respect
- gradually increasing trust

## Pattern Detection vs Consolidation

These are related but different.

### Pattern detection
Recognition that repeated material forms a meaningful structure.

### Pattern consolidation
Insertion of that structure into the model as a more stable understanding.

A detected pattern may eventually become:
- a structural relationship shift
- an expectation revision
- an insight event
- a ledger entry reflecting narrative meaning

## Why Patterns Improve Explainability

Patterns help explain why an event affected the system more than it would have in isolation.

For example:
- “this event mattered more because it confirmed a repeated pattern of dismissal”
- “this apology mattered because it was part of a longer repair trend”
- “this moment became meaningful because it fit a growing pattern of trust”

This is a major advantage over event-only systems.

## Example

Suppose several interactions each produce mild caution and disappointment. Any one interaction may seem small. But together they may form a pattern of unreliable reciprocity. Pattern consolidation may then create:
- lower structural trust
- stronger expectation of inconsistency
- increased relationship caution

This does not erase the individual events. It creates a higher-order understanding based on them.

## Design Rule

A pattern should only be consolidated when repetition or structure adds meaning that is not already captured by isolated entries alone.
